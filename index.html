03

PNG 解决的是「精确像素」与「透明度」问题

它的价值不是「文件一定更小」—— 而是每一个像素都可被精确还原

无损像素

解码输出与编码输入逐位一致，文字与线条边缘不糊

Alpha 透明

每像素可带独立透明度，UI 图标叠在任何背景上都干净

Chunk 可扩展

自描述的分块结构：新能力以新 Chunk 加入，旧解码器可跳过

流式可解码

顺序解析、逐行重建，天然适合硬件流水线与有限缓冲

典型场景 UI 图标 文字 / 线稿 屏幕截图 透明素材
注意

「无损」≠「文件一定更小」；扩展名 ≠ 品质保证。文件大小取决于图像内容、编码器与参数。

05

所有 Chunk 都遵循同一套四段式结构

Length + Type + Data + CRC —— 解码器因此可以顺序解析、跳过未知块、校验内容

Length4 B
Type4 B
Data0 … n B
CRC4 B
CRC-32 覆盖范围：Type + Data

把鼠标悬停到任意一段上，查看它的规则。

Length 只数 Data

读到 Length 后，解码器无需理解内容就能完整跳过这个 Chunk

Critical / Ancillary

Type 首字节大写 = Critical（IHDR/PLTE/IDAT/IEND，理解图像必需）；小写 = Ancillary，未知块可跳过

可跳过 ≠ 可忽略错误

CRC 校验失败、Critical 块无法识别，都是必须上报的错误

关键

每个 IDAT 都有自己的 CRC，但它们不是各自独立的压缩图片。Chunk 边界可以落在任何地方 —— 甚至是 DEFLATE Block、Scanline 或 Adler-32 的中间。

像素层

09

Inflate 的输出：带 Filter Type 的 Scanline

解压出来的不是像素 —— 每行开头还多一个 Filter Type 字节

F RGB RGB RGB RGB …
1 byte · Filter Type（0–4） filtered scanline bytes · 本行长度 = width × bpp

bpp = bytes per pixel

8-bit RGB 时 bpp = 3 —— Filter 的「左侧」指 3 个字节之前，不是 1 个

Filter 可逐行不同

每一行独立选择 0–4 中的一种，不要求全图统一

Filter Type ≠ 像素

它只属于滤波层，不参与颜色通道解释

10

五种 Filter，只是在选择「预测来源」

全部是可逆的字节级预测变换 —— 目的只有一个：让残差出现更多小值与重复

0None

Recon(x) = Filt(x)

不预测，原样存储

1Sub重点

Recon(x) = Filt(x) + Recon(a)

预测 = 左侧已重建字节，适合水平渐变

2Up重点

Recon(x) = Filt(x) + Recon(b)

预测 = 正上方已重建字节，适合垂直延续

3Average

Recon(x) = Filt(x) + ⌊(a+b)/2⌋

预测 = 左与上的平均（向下取整）

4Paeth

Recon(x) = Filt(x) + Paeth(a,b,c)

在 a / b / c 中选最接近 a+b−c 的那个

a = 左侧 · b = 上方 · c = 左上 —— 全部是已重建的字节；行首左侧、第一行上方等不存在的邻居一律按 0 计。所有运算按 byte 进行（mod 256）。

12

zlib ≠ DEFLATE

IDAT 承载的是 zlib 数据流；zlib 是封装，DEFLATE 才是里面的压缩编码

CMF · FLG2 B 头
DEFLATE 数据（LZ77 + Huffman）主体
Adler-324 B

本例 IDAT #1 的 Data 以 78 9C 开头 —— 这正是 zlib 头，且只在整条流开头出现一次

CRC-32 · 每个 Chunk 末尾

校验范围：该 Chunk 的 Type + Data

守护「文件层」的完整性

Adler-32 · zlib 流末尾

校验范围：zlib 所表示的未压缩数据

守护「压缩层」的完整性

两者覆盖范围与角色不同，不可互换；PNG 压缩方法 0 = zlib 格式承载 DEFLATE

LZ77：重复的内容，不再重复存储

Literal

Length / Distance

LZ77 只看到字节模式，不理解像素语义 —— Filter 创造的重复与小值，在这里兑现为压缩率

PNG vs Baseline JPEG

PNG 与常见 Baseline JPEG：不是谁取代谁，而是各管一段场景

PNG

  • 无损：解码 = 编码输入，逐位一致
  • 支持 Alpha 透明度
  • 锐利边缘、纯色区域不糊
  • Filter + DEFLATE：为可预测内容优化

UI · 图标 · 文字线稿 · 截图 · 需要精确像素的一切

VS

Baseline JPEG

  • 有损：用视觉近似换取体积
  • 无 Alpha
  • 边缘与文字易出现振铃伪影
  • DCT 频域量化：为连续色调优化

照片 · 自然图像 · 允许有损的连续色调内容

三个检查题 —— 带走它们，你就带走了整场分享
